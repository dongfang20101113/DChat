# 三端功能对等审计（Win32 / Android / Linux CLI）

> 为什么要有这份表：多会话（群聊 / 私聊）是**三端各自实现**的，而"服务端支持"不等于
> "每个端的用户都能用"。这份表逐项回答一个问题：**这一项，这个端的用户到底能不能操作？**
>
> 最后的"证据"列写的是**怎么验的**，不是"我看了代码觉得对"。

## 一、能力矩阵

图例：✅ 能操作且有证据 · ⚠️ 能操作但证据不完整 / 有已知限制 · ❌ 这个端没有

| 能力 | Win32 桌面端 | Android | Linux CLI | 备注 |
|---|---|---|---|---|
| 发起私聊 | ✅ `/dm` | ✅ `/dm` | ✅ `/dm` | 服务端指令，三端通用（`DM` 协议命令客户端从来不发，靠 `/dm` 补的） |
| 会话列表 / 切换 | ✅ 左栏 | ✅ 列表 | ✅ `/rooms` `/open` | |
| 建群（群 ID 自填、不可改） | ✅ | ✅ | ✅ `/create` | |
| 搜群（只有公开的能搜到） | ✅ | ✅ | ✅ `/find` | 新群默认不公开 |
| 申请入群 | ✅ | ✅ | ✅ `/join` | |

| 退出群聊 | ✅ | ✅ | ✅ `/leave` | |

| 删除本地聊天记录 | ✅ | ✅ | ❌ | 终端本来就一次性滚屏 |

**结论**：Win32 与 Android 基本对等；Linux CLI 补上了**所有服务端能力**（建群/搜群/入群/审核/踢人/解散/设置/黑名单），
差的是**只有图形界面才成立的东西**（免打扰、置顶、本地缓存上限、删除本地记录）和两处小缺口（改成员角色、看群公告）。

## 三、深色主题下"系统浅色元素"清单（Win32）

这类问题的共同点：**系统画的部分不吃 `WM_CTLCOLOR*`**，背景改了、边框/滚动条/菜单还是系统色。

| 元素 | 状态 |
|---|---|
| 输入框（EDIT）的 3D 边框 | ✅ 已修：去掉 `WS_EX_CLIENTEDGE`，由父窗口按 `g_palette->border` 自绘 1px 框 |
| 按钮 | ✅ 本来就是 `BS_OWNERDRAW` 自绘 |
| 滚动条 | ✅ 已用 `uxTheme` 跟深色（更早的改动） |
| 菜单栏 | ✅ 自绘（界面改版时换的） |
| `MessageBoxW` 系统弹窗 | ✅ 已修：设置里那两处校验（端口越界 / 地址为空）改成就地纠正输入框，不再弹系统对话框 |
| 文件选择框（`GetOpenFileNameW`） | ⚠️ 系统对话框，浅色。要改得自己写文件浏览器，代价与收益不成比例，**刻意保留** |

## 四、已知未做（诚实清单）

1. **Linux CLI 改成员角色**：服务端有 `GMEMBER`，CLI 没接（只有 `/members` 看）。加一条 `/role <昵称> <owner|admin|member>` 就够，没做是因为优先级低于审核/踢人。
2. **Linux CLI 看群公告**：`/set announcement` 能设，但没有 `/announce` 之类的查看入口。
3. **免打扰 / 置顶 / 本地缓存上限 / 删除本地记录**在 CLI 上**不做**：这几个是"图形界面的偏好"（未读圆点、列表排序、本地缓存预算），终端里没有对应概念。硬做只会变成"存了个值但没有任何效果"，比不做更糟。
4. **Android 没有真机验证**：本机无设备/模拟器，只有单测 + 离屏截图 + 连真实服务端的互操作测试。真机手感、输入法、DPI 还得人工看。
